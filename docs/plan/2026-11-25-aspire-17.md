# Move NimBus to Aspire 17

## Context

NimBus is on Aspire 13.6.5; the adapter kit is moving to 17.0.0. NimBus's hosting
packages (`Akaule.NimBus.AspireHosting`, `Akaule.NimBus.ServiceBusEmulator.AspireHosting`) are
still built against 13.6.5. They ran on 17 in the kit's check, but NimBus itself should build,
test and ship on 17.

Aspire 17 is not only a version bump:
- `Aspire.AppHost.Sdk` is obsolete (ASPIRE012). The replacement is `Microsoft.NET.Sdk` plus the
  `Aspire.Hosting.AppHost` and `Aspire.Hosting.Dotnet` packages.
- `AddProject<Projects.X>()` / `AddProject(name, path)` are obsolete (CS0618, an **error** in
  NimBus's Release build). The replacement, `AddDotnetProject(name, path)`, returns
  `IResourceBuilder<DotnetProjectResource>`, not `IResourceBuilder<ProjectResource>`.

Every Aspire dependency NimBus uses has a 17.0.0 release, including
`CommunityToolkit.Aspire.Hosting.DbGate`.

Scope (from `origin/master`): 2 AppHosts with 20 `AddProject` calls, 2 published hosting
packages (one with `ProjectResource` in its public API), 3 test projects, 4 workflows, ~18
project files with an Aspire pin, and a handful of docs.

## Changes

One PR, one commit per step. Release build must stay at 0 warnings after each.

### 1. Package pins
- Every `Aspire.*` reference 13.6.5 → 17.0.0 (AppHosts, both hosting packages,
  `Aspire.Azure.Messaging.ServiceBus` in the AspirePubSub / CloudEventsInterop / CrmErpDemo
  projects, `Aspire.Hosting.Testing`). They move together or restore fails with NU1605.
- `CommunityToolkit.Aspire.Hosting.DbGate` 13.6.1 → 17.0.0.
- `System.Security.Cryptography.Pkcs` pins in the two AppHosts: remove if NuGet audit is clean
  without them, otherwise keep (same handling as the 13.6.4 bump).
- `Microsoft.Extensions.ServiceDiscovery` / `Http.Resilience` in `NimBus.ServiceDefaults`: move
  only if Aspire 17 forces it (a downgrade error).

### 2. `Akaule.NimBus.ServiceBusEmulator.AspireHosting` (public API, RED-GREEN)
`src/NimBus.ServiceBusEmulator.AspireHosting/`. Two overloads and one handle name types Aspire 17
retires. Per `docs/versioning.md`, nothing is deleted: deprecate now, remove in the next major.
- **New**: `AddNimBusServiceBusEmulatorProject(builder, name, projectPath, port = null)`, built on
  `AddDotnetProject`, returning a new
  `NimBusServiceBusEmulatorProjectHandle(IResourceBuilder<DotnetProjectResource> Project, ConnectionString)`.
  A new name is needed because the existing path overload has the same parameters and a
  different return type. Adds the `Aspire.Hosting.Dotnet` package reference.
- **`[Obsolete]`**, still working, with a message naming the replacement:
  `AddNimBusServiceBusEmulator<TProject>(name, port)` and
  `AddNimBusServiceBusEmulator(name, projectPath, port)`, and `NimBusServiceBusEmulatorHandle`.
- **Unchanged**: the tool-package overload `AddNimBusServiceBusEmulator(name, port, version)` and
  `NimBusServiceBusEmulatorToolHandle` (what adapter repos and the kit use), and all of
  `Akaule.NimBus.AspireHosting`.
- Tests in `tests/NimBus.ServiceBusEmulator.Tests/AspireHostingTests.cs`: first a failing test
  for the new method (resource names, endpoint, connection string, health check, as the existing
  two assert); the two existing tests stay as characterization of the obsolete overloads.
- The private `Configure<TResource>` helper is already generic over the resource type and is
  reused as is.

### 3. `src/NimBus.AppHost`
- csproj: `Microsoft.NET.Sdk`, add `Aspire.Hosting.AppHost` and `Aspire.Hosting.Dotnet`, drop
  `IsAspireHost`; keep `AspireUseCliBundle` and `UserSecretsId`.
- `Program.cs`: the five `AddProject<Projects.X>` calls (provisioner, webapp, publisher,
  subscriber, warehouse-subscriber) become `AddDotnetProject(name, "<relative .csproj path>")`;
  the emulator uses the new `AddNimBusServiceBusEmulatorProject`; the
  `IResourceBuilder<ProjectResource>?` local becomes `DotnetProjectResource`.
- `AddAzureFunctionsProject<Projects.NimBus_Resolver>` stays (Aspire's guide says not to replace
  the specialized APIs). Its `ProjectReference` gets `IsAspireProjectResource="true"
  ReferenceOutputAssembly="false"` so `Projects.NimBus_Resolver` is still generated. The
  references to projects now added by path are removed.
- Resource names, endpoints (`webapp` `http`/`https` from its launch profile) and environment
  stay exactly as they are.

### 4. `samples/CrmErpDemo/CrmErpDemo.AppHost`
Same pattern: csproj as above; the `AddProject<Projects.X>` calls (provisioner, nimbus-ops,
crm-api, crm-adapter, erp-api, partner-portal, agent-zone, enrichment-agent, the three regional
hubs) become `AddDotnetProject`; the three `AddAzureFunctionsProject<T>` calls stay with marked
references; the `Contracts` reference stays ordinary (its type is used in code).
- Publish mode keeps its calls (`PublishAsAzureContainerApp`, `PublishAsAzureContainerAppJob`,
  `PublishWithContainerFiles`) on the new resource type. If one of them is not available for
  `DotnetProjectResource`, stop and re-plan that resource rather than drop publish behaviour.
- `tests/CrmErpDemo.AppHost.Tests`: `RegionalHubAppHostTests` looks hubs up with
  `OfType<ProjectResource>()` → `DotnetProjectResource`. The tests keep
  `CreateAsync<AppHost::Projects.CrmErpDemo_AppHost>`; confirm that type is still generated
  without the AppHost SDK, and if not, apply Aspire's documented marking.

### 5. CI
- `.github/workflows/dotnet.yml`, `nuget-publish.yml`, `dependency-security.yml`: the
  `aspire.cli@13.5.4` bundle setup → `17.0.0` (the comment there says to keep it in step).
- `.github/workflows/crm-erp-e2e.yml`: it reads the CLI version from the text
  `Aspire.AppHost.Sdk/x.y.z` in the AppHost csproj and fails if missing. Read it from the
  `Aspire.Hosting.AppHost` package version instead.

### 6. Docs
- `docs/building-adapters.md` "Run a local stack from packages": the AppHost snippet
  (`AddDotnetProject`, the Aspire 17 project file, an ordinary contracts reference).
- `src/NimBus.ServiceBusEmulator/README.md`: the new emulator-project method.
- `docs/worker-hosting.md` package pin; the two CrmErpDemo `docs/TDD.md` AppHost snippets;
  `samples/CrmErpDemo/README.md` line reference into `Program.cs`.

## Verification

1. `dotnet build src/NimBus.slnx -c Release`: 0 errors, 0 warnings, compared with the same build
   of `origin/master`.
2. `dotnet test src/NimBus.slnx -c Release --no-build`; report counts for
   `NimBus.AspireHosting.Tests`, `NimBus.ServiceBusEmulator.Tests` and `CrmErpDemo.AppHost.Tests`
   separately, and name the suites that skip locally (live SQL Server / Cosmos conformance).
3. Run `src/NimBus.AppHost` with the emulator (`--UseEmulator true`, Docker): every resource
   healthy, the WebApp answers 200, one sample publish is handled.
4. Run `CrmErpDemo.AppHost` on the emulator (`aspire start --isolated`): resources healthy, and
   the e2e live suite's smoke test if Functions Core Tools and Node are available here. If not,
   say exactly what was and was not started.
5. Publish-mode model: covered by `CrmErpDemo.AppHost.Tests` (`--operation publish`). `aspire
   deploy` to Azure is **not** run; the PR says so.
6. One review pass before the PR.

## Consumer impact (for the PR and release notes)

- Projects that reference `Akaule.NimBus.AspireHosting` or
  `Akaule.NimBus.ServiceBusEmulator.AspireHosting` must be on Aspire 17 after this release
  (an older AppHost fails restore with a downgrade error). The previous Aspire bumps shipped in
  minors with the same kind of note; this one crosses an Aspire major, so whether it ships as a
  minor or waits for a major is the maintainer's call. The PR flags it and does not decide it.
- Two emulator overloads and one handle type become `[Obsolete]`; nothing is removed.

## Not in this change

- `aspire run --watch` is not supported yet for projects added with `AddDotnetProject`.
