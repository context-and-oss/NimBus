CRM ⇄ ERP on NimBus

Two business systems keep accounts, customers and contacts in sync through Azure Service Bus. NimBus provides the topology, session ordering, the outbox and inbox, and the Resolver that records every message so an operator can see, resubmit or skip it in nimbus-ops.

Local run and Azure

The same AppHost runs the demo on your machine with aspire run and deploys it to Azure Container Apps with aspire deploy. These are the parts that change between the two.

ConcernLocal runAzure
Service BusNimBus Service Bus emulator, in process, no container neededAzure Service Bus; services connect with managed identity, SAS keys disabled
DatabasesSQL Server container with crm, erp and nimbus databases; Cosmos DB optional for the message storeAzure SQL, Basic tier, Entra-only authentication
HostingAspire on your machineAzure Container Apps; stateful apps pinned to one replica
Sign-inLocal development bypassNimBus Identity on nimbus-ops, crm-api and erp-api; adapters present a shared service key
TopologyProvisioner runs before the other services startContainer Apps job, started once after each deploy
Web UIsVite dev servers proxy /api to crm-api and erp-apiEach API serves its built UI from wwwroot
AlertsMailpit catches alert mail; webhooks may call local http receiversAlert mail and webhooks off
Database browsingDbGateNot deployed
