Messaging & delivery

Typed events, delivered in order

Publish typed events, route them by type, and process them in strict per-key order.

Event-driven pub/sub

Endpoints publish and consume typed events through Azure Service Bus topics and subscriptions: one topic per endpoint, routed by event type.

Session-based FIFO ordering

Messages sharing a [SessionKey] are handled strictly in order, one at a time. A stuck message blocks only its own session.

Request / response

Typed request/response conversations over Service Bus sessions, with timeout handling built in.

Schedule events for future delivery and cancel scheduled messages before they fire.

Reliability & recovery

Every failure has a defined path

Retries, dead-lettering, session blocking, and operator-driven recovery, with recorded outcomes for operators to investigate.

Retry policies with backoff

Retry policies per event type, exception type, or exception text, with fixed, linear, or exponential backoff, optional jitter, and support for server Retry-After hints.

Akaule.NimBus.CoreIRetryAfterHint

Permanent-failure classification

Unrecoverable exceptions are classified and dead-lettered immediately, so no retries are spent on a payload that can never succeed.

Akaule.NimBus.Core

Session blocking & deferral

When a message fails, later messages in the same session are deferred automatically until that session is unblocked at the receiving endpoint.

Akaule.NimBus.CoreAkaule.NimBus.ServiceBus

Deferred replay

Once a session is unblocked, its deferred messages are re-published in FIFO order, so the backlog drains itself.

Akaule.NimBus.ServiceBus

Resubmit / skip flows

Failed events can be resubmitted or skipped from the WebApp while keeping the Resolver's history consistent.

Akaule.NimBus.ManagerAkaule.NimBus.WebApp

Transactional outbox

Persist outgoing messages in a SQL Server outbox inside your business transaction; a dispatcher publishes them afterwards. The outbox ties the intent to publish to the database commit; consumers should remain idempotent.

Akaule.NimBus.Outbox.SqlServer

Consumer inbox

An opt-in inbox records each successfully handled MessageId per endpoint and skips a redelivered duplicate instead of running the handler again. It stores to SQL Server or Cosmos DB, with an in-memory store for tests.

Akaule.NimBus.Inbox.SqlServerAkaule.NimBus.MessageStore.CosmosDbUseInbox

Endpoint circuit breaker

An opt-in breaker stops an endpoint's receivers when handler failures pass a threshold, so queued messages stay on the subscription in order. It then probes with one session at a time and restores full concurrency once the probes succeed.

Akaule.NimBus.SDKWithCircuitBreaker

Pending handoff for long-running work

A handler can hand a message to an external job and return. The session stays blocked, in order, until the job reports back and the message is completed or failed, without the handler running again.

Akaule.NimBus.SDKMarkPendingHandoffIHandoffClient
Operations & observability

Inspect failures and recover work

The operational layer that raw Service Bus doesn't give you: a queryable audit of every message, a console to act on it, and automation for the rest.

Resolver state tracking

The Resolver records every message's outcome, such as Pending, Completed, Failed, Deferred, Dead-lettered, or Skipped, as one queryable audit trail.

Akaule.NimBus.MessageStore.Abstractions

Management WebApp

An authenticated console for inspecting endpoints, events, and messages, with live updates, resubmit/skip actions, alerts, and audit views.

Akaule.NimBus.WebApp

nb command-line tool

Provision infrastructure, apply topology, deploy apps, purge queues, and clean up sessions, from a laptop or a pipeline.

Akaule.NimBus.CommandLine

Health checks

Health probes for Service Bus and the message store, served on /health, /alive, and /ready.

Built-in middleware

Logging, OpenTelemetry metrics, and message validation ship as pipeline behaviors. Register the behaviors your application needs.

Failure notifications

Failures, dead-letters, and session blocks fan out to notification channels: a webhook, Microsoft Teams, or email.

Platform heartbeat

The WebApp sends a probe to every endpoint and the Resolver, and shows each one's status, round-trip time, and SDK version. Endpoints answer automatically, with no handler to write.

Akaule.NimBus.WebApp/Heartbeat

Failed messages page

One page lists every unresolved failure across the endpoints you can read, with a failures-over-time chart, filters, and list, by-endpoint, and by-error views. Resubmit or skip from any view.

Akaule.NimBus.WebApp/Failed

Role-based access

Reader, Contributor, and Owner roles apply site-wide and per endpoint, managed on the Access Control page. A separate PII Reader role sees raw values in [Sensitive] fields, which are otherwise redacted, partly revealed, or hashed.

Akaule.NimBus.WebApp[Sensitive]

Subscription incident response

When a producer floods the bus, site Owners can find the backlog on the Topology page and stop or clear it per subscription without touching other endpoints. Every action is audited.

Akaule.NimBus.WebApp/Topology

Private networking (preview)

Extension framework

Opt-in by design

Extensions package up services, middleware, and observers behind one registration. Without any, NimBus runs with its default core behavior.

INimBusExtension model

Extension packages register services, pipeline behaviors, and lifecycle observers through a single AddNimBus() call, composed with a fluent builder.

INimBusExtensionINimBusBuilder

Notifications extension

Configurable notifications on lifecycle events (failure and dead-letter by default) through webhook, Microsoft Teams, and email channels, or your own INotificationChannel, with per-channel severity filters and rate limiting.

Akaule.NimBus.Extensions.Notifications

Identity extension

ASP.NET Core Identity username/password sign-in for the WebApp, with email confirmation and reset flows, and optional dual login with Entra ID.

Akaule.NimBus.Extensions.Identity

Failure classification

Off by default. An operator asks for one failed or dead-lettered message to be classified, sending size-limited, redacted evidence to the TypeSafe provider. The result is stored with its history and comes with fixed guidance: retry may help, change likely required, investigate, or uncertain. It never changes message state.

Akaule.NimBus.Extensions.IntegrationIntelligence
